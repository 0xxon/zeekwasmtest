# Zeek Script Editor — WASM LSP Distribution

A browser-based Zeek script editor with auto-completion and hover documentation,
powered by the Zeek language server compiled to WebAssembly. No server-side
components required — everything runs in the browser.

## Quick Start

```sh
python3 serve.py 8080
# Open http://localhost:8080
```

Type `event` followed by a space and an event name prefix (e.g., `ssl_`), then
press Ctrl+Space or Shift+Tab to trigger completions. Hover over identifiers
to see documentation.

## What's in This Directory

```
dist/
  index.html              Demo page (minimal, self-contained)
  zeek-editor.js          Monaco editor setup + LSP integration
  zeek-lsp-worker.js      Web Worker that runs the WASM LSP

  coi-serviceworker.js    Enables COOP/COEP headers client-side
  serve.py                Dev server (adds required HTTP headers)
  pkg/                    WASM package (generated by wasm-pack)

    zeek_lsp_web_bg.wasm    WASM binary (~7 MB, contains full Zeek stdlib)
```

## Integrating into Your Website

### Option A: Drop-in (easiest)

Copy this entire directory into your project and include the HTML from
`index.html`. The editor fills its container and works out of the box.

### Option B: Custom integration

You need two things: the **WASM package** (`pkg/` directory) and a
**Web Worker** (`zeek-lsp-worker.js`).

#### 1. Copy files into your project

```
your-project/
  zeek-lsp/
    pkg/
      zeek_lsp_web.js
      zeek_lsp_web_bg.wasm
    zeek-lsp-worker.js
```

#### 2. Start the worker from your JS

```js
const worker = new Worker('./zeek-lsp/zeek-lsp-worker.js', { type: 'module' });

// Simple RPC helper
let nextId = 0;
const pending = new Map();

worker.onmessage = ({ data }) => {
  if (data.type === 'ready') { console.log('Zeek LSP ready'); return; }
  const p = pending.get(data.id);
  if (p) { pending.delete(data.id); p.resolve(data.result); }
};

function callLSP(msg) {
  return new Promise(resolve => {
    const id = ++nextId;
    pending.set(id, { resolve });
    worker.postMessage({ ...msg, id });
  });
}
```

**Note:** If you move `zeek-lsp-worker.js` relative to `pkg/`, update the
import path at the top of the worker file:
```js
import init, { Session } from './pkg/zeek_lsp_web.js';  // ← adjust this
```

#### 3. Request completions / hover

```js
// Completions (line and col are 0-based)
const items = await callLSP({
  type: 'complete',
  uri: 'file:///workspace/main.zeek',
  content: 'event ssl_',      // full file content
  line: 0,
  col: 10,
});
// → Array of LSP CompletionItem objects, or null

// Hover
const hover = await callLSP({
  type: 'hover',
  uri: 'file:///workspace/main.zeek',
  content: 'event connection_established(c: connection) { }',
  line: 0,
  col: 8,
});
// → LSP Hover object ({ contents, range }), or null
```

#### 4. Wire into your editor

See `zeek-editor.js` for a complete Monaco example. The same approach works
with CodeMirror or any other editor — the worker API is editor-agnostic.

## API Reference

The `Session` WASM class (used internally by the worker) exposes:

| Method | Arguments | Returns |
|---|---|---|
| `new Session()` | — | Session with bundled Zeek stdlib |
| `set_file(uri, content)` | `string, string` | — |
| `complete(uri, line, col)` | `string, u32, u32` | `CompletionItem[]` or `null` |
| `hover(uri, line, col)` | `string, u32, u32` | LSP `Hover` or `null` |

- **uri**: Any `file://` URI. Use a consistent URI per document.
- **line/col**: 0-based.
- Always call `set_file` (or pass `content` in the worker message) before
  `complete`/`hover` so the LSP has current source text.
- Completion returns a **plain array** (not `{ items: [...] }`).

## Hosting Notes

The `.wasm` file must be served with MIME type `application/wasm`.

For local development, use `serve.py` or the included `coi-serviceworker.js`
(which patches COOP/COEP headers client-side, no server config needed).

For production, set these HTTP headers on your server:

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

Most static hosts (GitHub Pages, Netlify, Vercel) support custom headers
via config files.
